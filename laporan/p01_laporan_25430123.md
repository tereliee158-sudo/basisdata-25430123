### 2. Tujuan Praktikum

Praktikum ini dilaksanakan untuk mengenali lingkungan kerja MariaDB serta memahami konfigurasi dasar yang digunakan dalam pengelolaan basis data. Kegiatan meliputi pemeriksaan versi server, mode SQL, daftar database, dan konfigurasi database proyek. Selain itu, praktikum bertujuan memahami penerapan hak akses berdasarkan peran pengguna agar setiap akun hanya dapat mengakses sumber daya sesuai dengan kewenangannya.

### 3. Hasil Praktikum

#### 3.1 Pemeriksaan Versi Server dan Akun Aktif

Pemeriksaan dilakukan menggunakan perintah berikut:

```sql
SELECT VERSION(), CURRENT_USER();
```

Hasil pemeriksaan menunjukkan bahwa server menggunakan MariaDB versi `10.4.32-MariaDB`, sedangkan akun yang aktif adalah `root@localhost`. Hasil tersebut menandakan bahwa koneksi ke server basis data berhasil dilakukan menggunakan akun administrator.

#### 3.2 Pemeriksaan Mode SQL

Untuk mengetahui pengaturan mode SQL yang sedang digunakan, dijalankan perintah:

```sql
SELECT @@sql_mode;
```

Hasil pemeriksaan menunjukkan tiga pengaturan aktif, yaitu `NO_ZERO_IN_DATE`, `NO_ZERO_DATE`, dan `NO_ENGINE_SUBSTITUTION`. Pengaturan tersebut berkaitan dengan validasi nilai tanggal serta penanganan ketika mesin penyimpanan yang diminta tidak tersedia.

#### 3.3 Pemeriksaan Daftar Database

Daftar database diperiksa melalui perintah:

```sql
SHOW DATABASES;
```

Hasilnya menampilkan tujuh database, yaitu `information_schema`, `kopma_123`, `mysql`, `performance_schema`, `perpus_123`, `phpmyadmin`, dan `test`.

Database `kopma_123` digunakan sebagai lingkungan latihan, sedangkan `perpus_123` disiapkan untuk pengembangan proyek bertema Perpustakaan. Database lainnya merupakan database sistem atau database bawaan lingkungan MariaDB dan XAMPP.

#### 3.4 Pemeriksaan Hak Akses Akun Latihan

Hak akses akun latihan diperiksa menggunakan perintah:

```sql
SHOW GRANTS FOR 'mhs_123'@'localhost';
```

Hasilnya menunjukkan bahwa akun `mhs_123` memiliki hak akses penuh pada database `kopma_123`. Namun, akun tersebut tidak diberikan hak akses global khusus terhadap seluruh database pada server. Konfigurasi ini membatasi ruang lingkup pekerjaan akun latihan pada database yang telah ditentukan.

#### 3.5 Pemeriksaan Hak Akses Akun Proyek

Pemeriksaan terhadap akun proyek dilakukan dengan perintah:

```sql
SHOW GRANTS FOR 'dev_123'@'localhost';
```

Hasil pemeriksaan menunjukkan bahwa akun `dev_123` memperoleh hak akses penuh pada database `perpus_123`. Akun tersebut tidak diberikan hak akses ke database latihan `kopma_123`. Pemisahan ini bertujuan menjaga agar kegiatan pengembangan proyek tidak bercampur dengan lingkungan latihan.

#### 3.6 Pemeriksaan Hak Akses Akun Tamu

Hak akses akun tamu diperiksa menggunakan perintah:

```sql
SHOW GRANTS FOR 'tamu_123'@'localhost';
```

Hasilnya menunjukkan bahwa akun `tamu_123` hanya memperoleh hak `SELECT` pada database `kopma_123`. Dengan demikian, akun ini dapat membaca data, tetapi tidak memiliki izin yang diberikan melalui konfigurasi tersebut untuk membuat tabel atau melakukan perubahan data.

#### 3.7 Pemeriksaan Konfigurasi Database Proyek

Konfigurasi database proyek diperiksa melalui perintah:

```sql
SHOW CREATE DATABASE perpus_123;
```

Hasilnya menunjukkan bahwa database `perpus_123` menggunakan character set `utf8mb4` dan collation `utf8mb4_unicode_ci`. Konfigurasi ini mendukung penyimpanan karakter Unicode, sehingga sesuai untuk data yang berpotensi memuat beragam karakter.

### 4. Analisis Pengujian Hak Akses

Pengujian hak akses dilakukan untuk mengetahui apakah pembatasan yang diterapkan pada setiap akun berjalan sesuai dengan tujuan konfigurasi.

#### 4.1 Pengujian Pembatasan Akses Database

Ketika akun `dev_123` mencoba mengakses database `kopma_123`, MariaDB menghasilkan **ERROR 1044**. Kesalahan ini menunjukkan bahwa akun tersebut tidak memiliki hak akses untuk menggunakan database latihan. Hasil tersebut sesuai dengan konfigurasi yang hanya memberikan hak akses penuh kepada `dev_123` pada database `perpus_123`.

#### 4.2 Pengujian Hak Membuat Tabel

Ketika akun `tamu_123` mencoba menjalankan perintah untuk membuat tabel pada database `kopma_123`, MariaDB menghasilkan **ERROR 1142**. Kesalahan tersebut terjadi karena akun tamu hanya diberikan hak `SELECT`, bukan hak `CREATE`. Oleh karena itu, akun tersebut tidak dapat membuat tabel melalui izin yang telah ditetapkan.

#### 4.3 Evaluasi Pembagian Hak Akses

Hasil pengujian memperlihatkan bahwa setiap akun memiliki kewenangan yang berbeda. Akun latihan digunakan untuk kegiatan pada database `kopma_123`, akun proyek mengelola database `perpus_123`, sedangkan akun tamu dibatasi pada kegiatan membaca data. Pembagian tersebut merupakan penerapan prinsip pembatasan hak akses (*least privilege*), yaitu memberikan izin sesuai kebutuhan pengguna.

### 5. Kesimpulan

Berdasarkan kegiatan praktikum, pemeriksaan lingkungan MariaDB berhasil dilakukan, meliputi identifikasi versi server, mode SQL, daftar database, hak akses akun, dan konfigurasi database proyek. Database `perpus_123` telah disiapkan menggunakan character set `utf8mb4` dan collation `utf8mb4_unicode_ci`.

Pengujian juga menunjukkan bahwa pembatasan hak akses dapat dibedakan berdasarkan fungsi setiap akun. ERROR 1044 muncul ketika akun proyek mencoba mengakses database latihan, sedangkan ERROR 1142 muncul ketika akun tamu mencoba membuat tabel. Hasil tersebut memperlihatkan pentingnya pengaturan hak akses dalam menjaga keamanan dan memisahkan lingkungan kerja basis data.
