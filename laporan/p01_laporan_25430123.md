## 1. Tujuan Praktikum

Praktikum ini bertujuan untuk mengenali lingkungan kerja MariaDB melalui XAMPP serta memahami pengelolaan basis data pada tingkat dasar. Kegiatan yang dilakukan meliputi pemeriksaan versi server, konfigurasi mode SQL, identifikasi basis data, dan pengaturan hak akses pengguna.

Selain itu, praktikum ini bertujuan untuk memahami perbedaan kewenangan setiap akun, menguji respons server ketika akses ditolak, mengonfigurasi autentikasi phpMyAdmin, serta menyiapkan repositori proyek menggunakan Git.

## 2. Ringkasan Dasar Teori

MariaDB merupakan sistem manajemen basis data relasional yang digunakan untuk menyimpan, mengelola, dan mengakses data menggunakan SQL. Dalam lingkungan XAMPP, MariaDB berperan sebagai server basis data yang dapat diakses melalui terminal maupun antarmuka phpMyAdmin.

Pengelolaan basis data memerlukan pengaturan hak akses agar setiap pengguna hanya dapat menjalankan operasi sesuai kewenangannya. Pembatasan ini merupakan penerapan prinsip *least privilege*, yaitu memberikan hak minimum yang diperlukan oleh suatu akun.

Selain pengelolaan basis data, Git digunakan untuk mencatat perubahan berkas proyek dan menyinkronkan pekerjaan ke repositori jarak jauh. Dengan demikian, hasil praktikum dapat didokumentasikan dan diperiksa kembali.

## 3. Hasil Langkah Percobaan

### 3.1 Pemeriksaan Versi Server dan Akun Aktif

Pemeriksaan lingkungan MariaDB dilakukan menggunakan perintah berikut:

```sql
SELECT VERSION(), CURRENT_USER();
```

Hasil pengujian menunjukkan bahwa server menggunakan MariaDB versi `10.4.32-MariaDB` dan akun yang aktif adalah `root@localhost`. Hasil tersebut membuktikan bahwa koneksi ke server berhasil dilakukan menggunakan akun administrator.

### 3.2 Pemeriksaan Mode SQL

Mode SQL diperiksa menggunakan perintah:

```sql
SELECT @@sql_mode;
```

Hasil pengujian menunjukkan bahwa mode SQL yang aktif terdiri atas `NO_ZERO_IN_DATE`, `NO_ZERO_DATE`, dan `NO_ENGINE_SUBSTITUTION`.

`NO_ZERO_IN_DATE` dan `NO_ZERO_DATE` berkaitan dengan penanganan nilai tanggal yang mengandung komponen nol. Sementara itu, `NO_ENGINE_SUBSTITUTION` mengatur penanganan ketika mesin penyimpanan yang diminta tidak tersedia.

Hasil ini merupakan konfigurasi yang terbaca pada server saat praktikum dilakukan. Nilainya belum mencakup `STRICT_TRANS_TABLES` sebagaimana konfigurasi yang dicontohkan dalam buku praktikum, sehingga perbedaan tersebut perlu dicatat sebagai bahan evaluasi konfigurasi.

### 3.3 Pemeriksaan Daftar Basis Data

Daftar basis data diperiksa menggunakan perintah:

```sql
SHOW DATABASES;
```

Hasil pemeriksaan menampilkan tujuh basis data, yaitu:

1. `information_schema`
2. `kopma_123`
3. `mysql`
4. `performance_schema`
5. `perpus_123`
6. `phpmyadmin`
7. `test`

Basis data `kopma_123` digunakan untuk latihan, sedangkan `perpus_123` disiapkan sebagai basis data utama proyek bertema Perpustakaan. Basis data lainnya merupakan basis data sistem atau bawaan lingkungan MariaDB dan XAMPP.

### 3.4 Pemeriksaan Hak Akses Akun Latihan

Hak akses akun latihan diperiksa melalui perintah:

```sql
SHOW GRANTS FOR 'mhs_123'@'localhost';
```

Hasil pemeriksaan menunjukkan bahwa akun `mhs_123` memperoleh hak akses penuh pada basis data `kopma_123`. Hak akses tersebut memungkinkan akun melakukan operasi yang diberikan pada basis data latihan tanpa memperoleh kewenangan global terhadap seluruh basis data di server.

### 3.5 Pemeriksaan Hak Akses Akun Proyek

Hak akses akun proyek diperiksa menggunakan perintah:

```sql
SHOW GRANTS FOR 'dev_123'@'localhost';
```

Hasil pemeriksaan menunjukkan bahwa akun `dev_123` memiliki hak akses penuh pada basis data `perpus_123`. Akun ini digunakan untuk kegiatan pengembangan proyek dan tidak diberikan hak akses penuh pada basis data latihan `kopma_123`.

Pemisahan tersebut membantu menjaga agar kegiatan latihan dan pengembangan proyek berjalan pada lingkungan yang berbeda.

### 3.6 Pemeriksaan Hak Akses Akun Tamu

Pemeriksaan akun tamu dilakukan menggunakan perintah:

```sql
SHOW GRANTS FOR 'tamu_123'@'localhost';
```

Hasil pengujian menunjukkan bahwa akun `tamu_123` memperoleh hak `SELECT` pada basis data `kopma_123`. Hak tersebut memungkinkan akun membaca data, tetapi tidak memberikan izin untuk membuat tabel.

Pembatasan ini kemudian diuji melalui percobaan pembuatan tabel yang menghasilkan `ERROR 1142`.

### 3.7 Pemeriksaan Konfigurasi Basis Data Proyek

Konfigurasi basis data proyek diperiksa menggunakan perintah:

```sql
SHOW CREATE DATABASE perpus_123;
```

Hasil pemeriksaan menunjukkan bahwa basis data `perpus_123` menggunakan karakter `utf8mb4` dan kolasi `utf8mb4_unicode_ci`. Pengaturan ini mendukung penyimpanan karakter Unicode dan pengurutan teks berdasarkan aturan kolasi yang digunakan.

### 3.8 Pengujian Login Root

Setelah kata sandi akun root diatur, pengujian dilakukan melalui dua cara. Pertama, login menggunakan opsi `-p` dan memasukkan kata sandi yang benar berhasil dilakukan. Kedua, login tanpa opsi `-p` menghasilkan pesan:

```text
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)
```

Hasil tersebut menunjukkan bahwa server menolak proses autentikasi ketika klien tidak mengirimkan kata sandi yang diwajibkan.

### 3.9 Pengujian Akses Database Sistem

Pengujian dilakukan menggunakan akun `mhs_123` dengan menjalankan perintah:

```sql
USE mysql;
```

Server memberikan respons:

```text
ERROR 1044 (42000): Access denied for user 'mhs_123'@'localhost' to database 'mysql'
```

Hasil ini menunjukkan bahwa akun berhasil dikenali oleh server, tetapi tidak memiliki izin untuk menggunakan basis data `mysql`.

### 3.10 Konfigurasi Autentikasi phpMyAdmin

Pada konfigurasi awal, phpMyAdmin menggunakan metode autentikasi `config` dan mencoba terhubung sebagai root tanpa mengirimkan kata sandi. Hal tersebut menyebabkan pesan penolakan akses.

Konfigurasi kemudian diubah menjadi metode `cookie` melalui berkas `config.inc.php` dengan pengaturan:

```php
$cfg['Servers'][$i]['auth_type'] = 'cookie';
```

Setelah perubahan disimpan dan halaman dimuat ulang, formulir login phpMyAdmin berhasil ditampilkan. Selanjutnya, login menggunakan akun root berhasil dilakukan dan dashboard phpMyAdmin dapat diakses.

## 4. Jawaban Titik Analisis

### 4.1 Titik Analisis 1 — Hubungan MySQL dan MariaDB

Walaupun beberapa antarmuka atau dokumentasi masih menggunakan istilah MySQL, server yang berjalan pada lingkungan praktikum ini adalah MariaDB. Hal tersebut dapat diketahui melalui hasil perintah `SELECT VERSION()`.

Ketika menemukan kendala, dokumentasi resmi MariaDB sebaiknya menjadi rujukan utama apabila masalah berkaitan dengan fitur atau perilaku khusus MariaDB. Dokumentasi MySQL tetap dapat digunakan untuk memahami konsep SQL yang berlaku pada keduanya, tetapi kesesuaian sintaks dan perilaku fitur perlu diperiksa terlebih dahulu.

Selain dokumentasi resmi, pesan kesalahan yang muncul dapat digunakan sebagai petunjuk untuk mencari solusi. Informasi dari forum atau sumber lain sebaiknya dibandingkan dengan dokumentasi resmi sebelum diterapkan.

### 4.2 Titik Analisis 2 — Pengujian Login Root

Ketika login dilakukan menggunakan perintah `mysql -u root` tanpa opsi `-p`, MariaDB menampilkan `ERROR 1045` dengan keterangan `using password: NO`. Keterangan tersebut berarti klien tidak mengirimkan kata sandi pada percobaan login.

Sebaliknya, login menggunakan opsi `-p` dan memasukkan kata sandi yang benar berhasil dilakukan. Dengan demikian, pengujian membuktikan bahwa akun root memerlukan autentikasi menggunakan kata sandi.

### 4.3 Titik Analisis 3 — Hak Akses information_schema dan Database mysql

Basis data `information_schema` dapat terlihat melalui `SHOW DATABASES` karena MariaDB menyediakan informasi metadata yang dapat diakses pengguna sesuai kewenangannya. Kemunculan nama basis data tersebut tidak berarti pengguna memperoleh akses bebas ke seluruh basis data sistem.

Pada pengujian ini, akun `mhs_123` tidak dapat menjalankan `USE mysql` dan menerima `ERROR 1044`. Hal tersebut menunjukkan bahwa akun telah dikenali, tetapi tidak mempunyai izin yang diperlukan untuk menggunakan basis data tersebut.

Perbedaan `ERROR 1044` dan `ERROR 1045` terletak pada tahap penolakan. `ERROR 1044` berkaitan dengan tidak adanya hak akses terhadap basis data tertentu, sedangkan `ERROR 1045` berkaitan dengan penolakan autentikasi atau akses login, misalnya karena kata sandi tidak dikirimkan atau tidak sesuai.

### 4.4 Titik Analisis 4 — Keamanan Mode Cookie

Mode `cookie` lebih sesuai untuk penggunaan phpMyAdmin secara interaktif karena pengguna diminta memasukkan kredensial melalui halaman login. Dengan metode ini, kata sandi tidak perlu dituliskan langsung dalam konfigurasi koneksi phpMyAdmin.

Sebaliknya, mode `config` dapat menyimpan informasi autentikasi di dalam berkas konfigurasi. Apabila berkas tersebut dapat dibaca oleh pihak yang tidak berwenang, kredensial yang tersimpan berisiko diketahui. Oleh karena itu, mode `cookie` membantu mengurangi risiko penyimpanan kata sandi secara langsung dalam konfigurasi.

Meskipun demikian, keamanan tetap bergantung pada perlindungan berkas konfigurasi, pengelolaan akun, dan pengamanan lingkungan server.

### 4.5 Perbedaan ERROR 1044, ERROR 1045, dan ERROR 1142

Ketiga kode kesalahan tersebut menunjukkan jenis penolakan yang berbeda.

| Kode | Makna | Contoh Pengujian |
|---|---|---|
| `ERROR 1044` | Pengguna tidak memiliki izin untuk mengakses basis data tertentu. | `mhs_123` mencoba menggunakan database `mysql`. |
| `ERROR 1045` | Proses autentikasi atau login ditolak. | `root` mencoba login tanpa mengirimkan kata sandi. |
| `ERROR 1142` | Pengguna tidak memiliki izin untuk menjalankan operasi tertentu pada objek basis data. | `tamu_123` mencoba membuat tabel tanpa hak `CREATE`. |

Perbedaan tersebut penting untuk menentukan sumber masalah. Kesalahan autentikasi perlu diperiksa melalui kredensial dan metode login, sedangkan kesalahan hak akses perlu diperiksa melalui izin yang diberikan kepada akun.

## 5. Hasil Latihan dan Modifikasi

### 5.1 Pembagian Hak Akses Pengguna

Pengujian menunjukkan bahwa akun latihan tidak dapat menggunakan basis data sistem `mysql`, sedangkan akun tamu tidak dapat membuat tabel. Hasil tersebut sesuai dengan pembatasan hak akses yang diterapkan.

### 5.2 Pengujian Hak Membuat Tabel

Ketika akun `tamu_123` menjalankan perintah pembuatan tabel pada basis data latihan, MariaDB memberikan `ERROR 1142`. Penolakan ini terjadi karena akun hanya memiliki hak `SELECT`, sementara pembuatan tabel memerlukan hak `CREATE`.

Hasil tersebut menunjukkan bahwa pemberian hak akses perlu disesuaikan dengan kebutuhan setiap pengguna.

### 5.3 Evaluasi Konfigurasi

Hasil pemeriksaan mode SQL menunjukkan bahwa konfigurasi yang aktif belum sama dengan konfigurasi contoh dalam buku praktikum. Perbedaan tersebut perlu dievaluasi sebelum konfigurasi diubah agar penyesuaian dilakukan secara terencana.

Selain itu, autentikasi phpMyAdmin telah diubah dari mode `config` menjadi `cookie` dan berhasil menampilkan halaman login serta dashboard setelah autentikasi berhasil.
